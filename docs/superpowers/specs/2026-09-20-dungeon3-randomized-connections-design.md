# Dungeon3 随机层级与连接类型设计

## 背景

当前 Dungeon3 生成器把房间位置固定在三排，并把三排分别赋予 2、1、0 层。这样会让所有纵向房间连接都成为楼梯，地图的视觉节奏和可用连接类型都高度重复。此前为了修复“门出现在楼梯上”，如果简单禁止楼梯门，又会使地图几乎没有合法门。

本设计调整的是生成规则，而不是继续为固定布局增加随机装饰。

## 目标

1. 房间层级不再由固定排号决定；同一地图中应能出现同层连接和跨层连接。
2. 跨层连接只使用楼梯。
3. 同层、跨水连接可使用平桥或拱桥；拱桥必须使用 TMX 中 `Arches_columns` 的真实资源。
4. 同层、非跨水连接可使用实际墙体上的门洞；门关闭时阻挡，打开后移除阻挡并使用真实开启帧。
5. 楼梯、门、拱桥是互斥的连接表现，门不能落在楼梯或楼梯落点上。
6. 水下墙倒影只允许出现在实际墙体占用的水格中，不能因为邻近普通地面就出现在开阔河水中央。
7. 生成后的关键点在门打开的路线验证中保持可达；装饰和连接类型不能破坏既有安全路线。

## 非目标

- 不重新制作或生成新的 PNG 素材。
- 不改变房间主题、战斗、宝箱、陷阱或多人同步协议的语义。
- 不要求每张地图同时包含所有连接类型，但跨多个种子与楼层的生成样本必须能覆盖楼梯、门洞和平桥/拱桥。
- 不把门作为水边或地图边缘的装饰性“假入口”。

## 生成模型

### 房间层级

房间仍使用现有槽位图和房间图连接，以控制地图尺寸和路径验证成本；层级改为在生成阶段随机赋值。赋值规则如下：

- 层级取值为 0、1、2。
- 相邻房间层级差最多为 1，避免生成无法表达的垂直断层。
- 每张地图尽量覆盖至少两种层级；如果随机结果不满足，生成尝试应重新赋值或重建该次布局。
- 层级不再与房间所在的三排绑定，因此北向、南向和东西向连接都可能是同层或跨层。

### 连接分类

每条图连接在生成时计算 `levelDelta`、方向和是否跨越水域，并只选择一个连接结构：

| 条件 | 结构 | 说明 |
| --- | --- | --- |
| `levelDelta !== 0` | `stairs` | 生成楼梯和高低层边界开口，不生成门 |
| `levelDelta === 0` 且跨水 | `bridge` | 在平桥和拱桥之间随机选择；拱桥使用真实 `bridgeArch` 组装件 |
| `levelDelta === 0` 且不跨水 | `door` 或普通开放连接 | 门只放在连接端真实的侧墙/墙洞中，不能漂浮在水中 |

同一条连接只能有一种主结构。门的碰撞、桥面、楼梯台阶和高低层边界都必须引用该连接的 `pathId`，方便测试互斥关系。

### 门洞

门洞由连接端墙体产生，而不是由“房间没有北向连接”这种反向条件产生。侧向门需要使用现有门素材的旋转/方向变换，关闭和开启状态必须保持同一方向与占位范围。

- `door.opened === false` 时，门碰撞加入 `geometry.solids`。
- 打开时移除对应 `doorId` 的碰撞，并渲染 TMX 门动画的开启帧。
- 门必须属于具体墙段和 `pathId`；其碰撞范围不得与 `stairs` 或 `elevations` 的过渡区域重叠。

### 桥

只有实际跨水的同层连接才写入 `geometry.bridges`。桥型随机性保留，但桥型选择不能改变路径的可达性：

- 平桥继续使用桥面变体。
- 拱桥使用 `rules.assemblies.bridgeArch`，其来源必须是 `Arches_columns`。
- 拱桥资源只作为桥结构渲染，不进入普通房间装饰池。

## 水域墙倒影

`underwater-ruin` 的候选位置由 `geometry.walls` 生成实际墙体占用格集合后筛选。候选组装件至少有一个格与可见墙体占用格重合；墙洞部分不算墙体。普通 `floor` 邻接、桥邻接或河岸邻接本身不足以允许该素材。

普通水面波纹仍可在开阔水域出现，但它们必须使用独立的 `water-detail` 层，不能复用墙体倒影素材。

## 生成验证

验证需要覆盖以下不变量：

- 同层房间连接不会被错误标记为楼梯。
- 跨层连接一定有楼梯，且对应连接没有门。
- 门只属于同层连接，且门碰撞存在于关闭状态。
- 桥只表示跨水连接，拱桥计划包含 `Arches_columns` 素材。
- 关键点在“所有门已打开”的路线模型中可达。
- 水下墙倒影的每个组装件都由真实墙格支撑。
- 多个固定种子和楼层组合能观察到层级、楼梯、门洞、平桥和拱桥的变化。

## 影响范围

- `web/src/lib/games/dungeon/map-generator.js`：层级赋值、连接分类、墙段与门生成。
- `web/src/lib/games/dungeon/dungeon3-renderer.js`：方向化墙/门的渲染计划与连接互斥检查。
- `web/src/lib/games/dungeon/dungeon3-dressing.js`：墙体支撑的水下倒影筛选。
- `scripts/extract-dungeon3-rules.mjs` / `dungeon3-data.js`：如方向化门需要数据化组装件，则补充来源可追溯的变换数据。
- Dungeon3 结构、丰富度、地图生成和渲染测试：增加随机连接覆盖与错误组合回归测试。

## 验收标准

在完整 Web 测试和构建通过的前提下，抽样检查多个种子与楼层应满足：

- 不再出现所有纵向连接都是楼梯的固定模式。
- 不出现门压在楼梯或楼梯落点上的情况。
- 门确实位于同层连接的墙体上，并且开门后角色可以通过。
- 拱桥在生成计划中使用真实拱桥资源，而不是用普通水岸素材伪装。
- 红框所示的开阔河心水域不再出现墙倒影；有墙的水域仍保留该表现。
