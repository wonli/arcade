# Xiangqi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add rules-correct Chinese Chess to AQI Arcade with human-vs-bot as the default launcher mode, two-player online play, Arcade-consistent UI, server-authoritative moves, resign/rematch, localized copy, and first-class replay/history integration.

**Architecture:** Xiangqi follows the existing server-owned turn-based path used by Gomoku and International Chess. A focused Go rules engine under `game/xiangqi/` owns legality, check/finish detection, reset/resign, and bot search; `arcade/` only wires rooms and bot turns. The Svelte frontend owns board rendering, interaction, assets, localization, recording, and replay while consuming server-provided legal moves rather than duplicating rule logic.

**Tech Stack:** Go, AQI WebSocket actions, Svelte 5, Node test runner, SVG assets, existing snapshot replay infrastructure.

**Spec:** `docs/superpowers/specs/2026-09-23-xiangqi-design.md`

## Global Constraints

- Game id is exactly `xiangqi`.
- Standard 9×10 Xiangqi rules; Red moves first.
- Launcher defaults Xiangqi to one human vs AQI BOT; human is Red in v1.
- Two-player online mode remains available.
- English and Simplified Chinese copy are required.
- Page/HUD/buttons/result dialogs reuse current Arcade styling; Xiangqi-specific styling is limited to the board and pieces.
- Server is authoritative for legal moves and game completion.
- Replay remains Xiangqi-owned and uses the existing persisted replay lifecycle; no `localStorage` history.
- No clocks, Elo, side selection, opening books, notation import/export, external engines, or new generic board-game framework in v1.
- Wikimedia piece artwork may only be committed after individual source/license verification and must be credited in `ASSET_CREDITS.md`.

## Review Focus

- A move that is geometrically valid but exposes the moving general must be rejected by the server.
- Cannon captures must require exactly one screen while non-capturing cannon moves require zero screens.
- Horse-leg and elephant-eye blockers must be evaluated from the current authoritative board, including after captures.
- A Black-side browser must render the board rotated while preserving server coordinates and legal target submission.
- Bot/rematch/replay flows must not leave stale `legalMoves`, stale selection, or stale finished-state metadata after state reset.

- [ ] **Step 8: Implement legal filtering, check detection, terminal state, and resign**

Required flow:

```go
func LegalMoves(state State, color Color) []MoveData {
    pseudo := pseudoMoves(state, color)
    legal := make([]MoveData, 0, len(pseudo))
    for _, move := range pseudo {
        next := makeMoveUnchecked(state, move)
        if !inCheck(next, color) { legal = append(legal, move) }
    }
    return legal
}

func (g *Game) finishIfNeeded() {
    moves := LegalMoves(g.state, g.state.Turn)
    g.state.Check = inCheck(g.state, g.state.Turn)
    g.state.Legal = moves
    if len(moves) == 0 {
        g.state.Status = game.StatusFinished
        g.state.Winner = opposite(g.state.Turn)
        g.state.Legal = nil
    }
}
```

`inCheck` must include flying-general attack and normal enemy attacks without recursively calling `LegalMoves`.
